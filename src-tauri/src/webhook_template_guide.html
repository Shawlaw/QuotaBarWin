Webhook 通知指南

说明「设置 → 通知 → Webhook」的两种发送格式，以及自定义消息模板支持的占位符。

中文 English

两种发送格式

  • 默认（模板留空）：每次刷新产生的所选事件打包为一个 JSON 批量请求，以 application/json POST 到你填写的地址。
  • 自定义模板：填写模板后，每条所选事件单独渲染并发送一次请求。渲染结果是合法 JSON 时以 application/json 发送（适合钉钉、飞书、企业微信等机器人接口），否则以 text/plain; charset=utf-8 发送（适合通用接收端、日志收集）。

模板只做占位符替换，不解析其它语法；不认识的占位符会原样保留。模板正文不支持 ${secret:} 等密钥引用（只有 Webhook URL 支持），避免把密钥写进发往外部服务的内容里。

可以配置多个 Webhook 端点：事件会同时发送到所有已启用的端点，每个端点独立配置名称、URL、模板、超时与启用开关，任一端点失败不影响其它端点。

默认 JSON 批量格式

留空模板时，请求体结构如下（字段均为 camelCase）：

{
  "schemaVersion": 1,
  "app": "QuotaBarWin",
  "appVersion": "1.6.0(a1b2c3d)",
  "sentAt": "2026-10-07T01:35:28.107592100+00:00",
  "events": [
    {
      "id": 7,
      "occurredAt": "2026-10-06T22:35:28.107592100+00:00",
      "eventType": "quota-reset",
      "severity": "positive",
      "providerId": "kimi-coding-2",
      "providerName": "Kimi",
      "windowId": "300-minute",
      "windowLabel": "5小时限",
      "details": {
        "remainingPercent": 100.0,
        "resetAt": "2026-10-07T03:35:14.207781Z",
        "usedPercentBefore": 37.0,
        "usedPercentAfter": 0.0
      }
    }
  ]
}

与应用无关的事件（如应用启动）中，providerId / windowId / windowLabel / details 可能缺省。details 的具体键随事件类型不同，见下文事件类型表。

模板占位符

占位符 替换为
{{message}} 本地化的通知正文（与 Windows 通知相同，末尾已附带事件发生的本地时间 MM-DD HH:mm）
{{eventType}} 事件类型标识，如 quota-reset
{{severity}} 级别：info / positive / warning / error
{{providerId}} 提供方实例 ID（与应用无关的事件为空字符串）
{{providerName}} 提供方显示名（如 Kimi）
{{windowId}} 额度窗口 ID（如 300-minute）
{{windowLabel}} 额度窗口显示名（如 5小时限）
{{occurredAt}} 事件发生时刻（RFC 3339 / UTC）
{{app}} 固定值 QuotaBarWin
{{appVersion}} 应用版本（含短 commit，如 1.6.0(a1b2c3d)）
{{eventJson}} 该事件的完整 JSON 对象（紧凑序列化），想在自定义 JSON 结构里内嵌原始数据时使用
想拿 details 里的具体数值（如剩余百分比）？用 {{eventJson}} 内嵌整份事件数据，或由接收端解析 {{message}} 文本。

模板示例

钉钉自定义机器人

{"msgtype":"text","text":{"content":"[QuotaBarWin] {{message}}"}}

飞书自定义机器人（text 消息）

{"msg_type":"text","content":{"text":"[QuotaBarWin] {{providerName}} {{windowLabel}}：{{message}}"}}

通用 JSON 转发（保留原始事件数据）

{"source":"{{app}} {{appVersion}}","occurredAt":"{{occurredAt}}","event":{{eventJson}}}

纯文本（渲染结果不是合法 JSON，会按 text/plain 发送）

[QuotaBarWin] {{message}}（类型：{{eventType}}，级别：{{severity}}）

事件类型

eventType 含义 级别
quota-reset 额度重置：上一周期有消耗的窗口滚动，额度恢复——包括窗口比之前宣布的时间提前滚动、或边界已过但提供方尚未更新重置时间的情况（details 含 remainingPercent、usedPercentBefore/After、新周期 resetAt） positive
quota-reset-time-changed 额度到期时间变更：上一周期没有任何消耗的窗口滚动（details 含 resetAtBefore 与新 resetAt）。默认不发通知，需在设置中单独勾选 info
quota-recovered-unexpected 额度异常回升：重置时间完全未变（提供方仍承诺同一周期）时已用额度大幅回落（≥20%），例如周期中途额度被部分归还 warning
quota-exhausted 额度已用尽（剩余 ≤ 0.5%） error
quota-low 额度低于通知设置中的警告阈值 warning
provider-error 提供方刷新失败（details 含脱敏后的 error） error
provider-recovered 提供方刷新恢复正常 info
app-update-applied 应用升级完成（details 含 version） positive
app-started 应用启动。默认不发通知 info

其它行为说明

  • Webhook URL 支持 ${secret:NAME}、${env:NAME}、${file:C:\path\secret.txt} 密钥引用，避免把带 token 的地址明文写进配置文件。
  • 请求遵循应用的网络代理设置；超时时间可在设置中调整（1–60 秒）。
  • 通知在变化得到确认后的下一次刷新时送达（默认间隔 300 秒，可在设置中调小）；应用未运行时不补发。
  • 「发送测试通知」使用当前界面填写的配置（包括模板草稿），无需先保存；测试事件类型为 test-notification，不会写入事件历史。
  • 发送失败只记录脱敏后的本地日志（quotabarwin.log），不会重试。
  • Webhook 会把额度事件数据发送到你指定的外部地址，请只填写自己信任的服务。

Webhook Guide

The two delivery formats of Settings → Notifications → Webhook, and the placeholders supported by the custom body template.

中文 English

Two delivery formats

  • Default (empty template): the selected events of one refresh are delivered as a single JSON batch request, POSTed with application/json to your endpoint.
  • Custom template: with a template configured, each selected event is rendered and delivered as its own request. A rendered body that parses as JSON is sent as application/json (DingTalk, Feishu/Lark, WeCom bots, …); anything else is sent as text/plain; charset=utf-8 (generic receivers, log collectors).

The template is plain placeholder substitution with no other syntax; unknown placeholders are left untouched. Secret references such as ${secret:} are resolved in the webhook URL only, never inside the body, so credentials never end up in the content you send to an external service.

You can configure multiple webhook endpoints: events fan out to every enabled endpoint, and each endpoint carries its own name, URL, template, timeout, and enable switch. One endpoint failing never blocks the others.

Default JSON batch format

With an empty template the request body looks like this (all camelCase):

{
  "schemaVersion": 1,
  "app": "QuotaBarWin",
  "appVersion": "1.6.0(a1b2c3d)",
  "sentAt": "2026-10-07T01:35:28.107592100+00:00",
  "events": [
    {
      "id": 7,
      "occurredAt": "2026-10-06T22:35:28.107592100+00:00",
      "eventType": "quota-reset",
      "severity": "positive",
      "providerId": "kimi-coding-2",
      "providerName": "Kimi",
      "windowId": "300-minute",
      "windowLabel": "5h limit",
      "details": {
        "remainingPercent": 100.0,
        "resetAt": "2026-10-07T03:35:14.207781Z",
        "usedPercentBefore": 37.0,
        "usedPercentAfter": 0.0
      }
    }
  ]
}

For app-level events (such as app started), providerId / windowId / windowLabel / details may be absent. The keys inside details depend on the event type — see the event type table below.

Template placeholders

Placeholder Replaced with
{{message}} the localized notification text (same as the Windows toast; ends with the local event time MM-DD HH:mm)
{{eventType}} event type identifier, e.g. quota-reset
{{severity}} severity: info / positive / warning / error
{{providerId}} Provider instance id (empty string for app-level events)
{{providerName}} Provider display name (e.g. Kimi)
{{windowId}} quota window id (e.g. 300-minute)
{{windowLabel}} quota window display name (e.g. 5h limit)
{{occurredAt}} when the event occurred (RFC 3339 / UTC)
{{app}} the constant QuotaBarWin
{{appVersion}} app version with short commit, e.g. 1.6.0(a1b2c3d)
{{eventJson}} the full JSON object of the event (compact serialization) for embedding raw data in a custom JSON structure
Need concrete values from details (like the remaining percent)? Embed the whole event with {{eventJson}}, or parse the {{message}} text on the receiving side.

Template examples

DingTalk custom bot

{"msgtype":"text","text":{"content":"[QuotaBarWin] {{message}}"}}

Feishu/Lark custom bot (text message)

{"msg_type":"text","content":{"text":"[QuotaBarWin] {{providerName}} {{windowLabel}}: {{message}}"}}

Generic JSON relay (keeps the raw event)

{"source":"{{app}} {{appVersion}}","occurredAt":"{{occurredAt}}","event":{{eventJson}}}

Plain text (not valid JSON, so it is sent as text/plain)

[QuotaBarWin] {{message}} (type: {{eventType}}, severity: {{severity}})

Event types

eventType Meaning Severity
quota-reset a window that consumed quota in the previous cycle rolled over and the quota is back — including windows that roll earlier than previously announced, or whose boundary already passed while the provider lags the reset time (details include remainingPercent, usedPercentBefore/After, and the new cycle's resetAt) positive
quota-reset-time-changed a window that consumed nothing rolled over (details include resetAtBefore and the new resetAt). Excluded from notification defaults; select it in Settings to notify info
quota-recovered-unexpected used quota dropped sharply (≥20%) while the reset time is unchanged (the provider still promises the very same cycle), e.g. quota granted back mid-cycle warning
quota-exhausted quota exhausted (remaining ≤ 0.5%) error
quota-low quota dropped below the warning threshold configured in the notification settings warning
provider-error Provider refresh failed (details include the redacted error) error
provider-recovered Provider refresh recovered info
app-update-applied application update applied (details include version) positive
app-started application started. Excluded from notification defaults info

Other behavior notes

  • The webhook URL supports ${secret:NAME}, ${env:NAME}, and ${file:C:\path\secret.txt} references, so token-bearing addresses stay out of the plain-text config file.
  • Requests follow the app proxy settings; the timeout is configurable (1–60 seconds).
  • Notifications are delivered on the next refresh after a change is confirmed (default interval 300 seconds, adjustable); nothing is sent retroactively while the app is not running.
  • "Send test notification" uses the current form values (including the template draft) without saving first; the test event type is test-notification and is not written to the event history.
  • Delivery failures are only written to the redacted local log (quotabarwin.log); there are no retries.
  • A webhook sends your quota event data to an external address you choose, so only point it at services you trust.
