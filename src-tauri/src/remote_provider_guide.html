Remote Provider Guide

Install quota providers from a hosted manifest + script, without bundling them into the app.

How it works

  1. You provide a manifest URL (a JSON file that describes the provider).
  2. QuotaBarWin fetches the manifest, verifies the source checksum, and downloads the source script referenced by the manifest.
  3. The script is cached locally and executed with the declared runtime (for example node, python, or an absolute path).
  4. On every refresh QuotaBarWin runs the cached script and parses the output into quota windows.

Manifest format

Save the manifest as provider.json next to your source script.

{
  "schemaVersion": 1,
  "id": "kimi-coding",
  "displayName": "Kimi Coding Usage",
  "description": "Kimi coding quota usage via remote provider script.",
  "runtime": "node",
  "entry": "provider.cjs",
  "requiredEnvVars": ["KIMI_API_KEY"],
  "output": "provider-snapshot-v1",
  "permissions": ["env:KIMI_API_KEY"],
  "checksums": {
    "source": "sha256:<hex>"
  }
}
FieldRequiredDescription
schemaVersionyesMust be 1.
idyesUnique provider id. Must not conflict with an existing provider.
displayNameyesHuman-readable name shown in the UI.
descriptionnoShort description.
runtimeyesRuntime used to execute entry. Common values: node, python, pwsh, bash, or an absolute path.
entryyesSource file name. Relative paths are resolved against the manifest URL; absolute HTTPS URLs are also supported.
requiredEnvVarsnoEnvironment variables required by the script. Shown in the install confirmation dialog.
outputyesOutput contract. Use provider-snapshot-v1.
permissionsnoDeclared capabilities (informational). Use env:<NAME> to document env vars.
checksums.sourcenoSHA-256 checksum of the source file. Required for auto-update. Format: sha256:<hex>.

Source script output contract

When output is provider-snapshot-v1, the script must print a single JSON object to stdout. id, name, and source are optional and default to the manifest values.

{
  "status": "ok",
  "updatedAt": "2026-06-12T10:00:00.000Z",
  "windows": [
    {
      "id": "weekly",
      "label": "Weekly limit",
      "used": 12,
      "limit": 100,
      "unit": "requests",
      "usedPercent": 12,
      "remainingPercent": 88,
      "resetAt": "2026-06-19T10:00:00.000Z",
      "resetText": null,
      "confidence": "exact"
    }
  ],
  "metadata": {}
}

Security checklist

  • Only install remote providers from sources you trust.
  • Review the source URL, runtime, and required env vars in the confirmation dialog.
  • Prefer manifests that include checksums.source; without it QuotaBarWin cannot auto-update safely.
  • The cached source file lives in the app data directory under providers/remote/<id>/.

Examples

The examples/remote-providers/ directory in the QuotaBarWin repository contains complete sample providers for Kimi, BigModel (Zhipu), and Codex usage.

To host your own provider, upload a directory containing provider.json plus the source file and paste the raw provider.json URL into QuotaBarWin.

Updating a remote provider

If the manifest contains checksums.source, QuotaBarWin can detect source changes:

  • Auto-update: enabled per provider during install; updates are applied silently when the checksum differs.
  • Manual update: use the Check Updates / Apply Update buttons in Settings.

If checksums.source is missing, updates must be applied by removing and re-adding the provider.
