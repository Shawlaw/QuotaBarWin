远程 Provider 指南

通过托管的 manifest 和脚本安装额度 Provider，无需把 Provider 打包进主程序。

中文 English

工作方式

  1. 在设置页提供 registry URL 或本地路径，例如 registry.json。
  2. QuotaBarWin 读取 registry，拉取每个 Provider manifest，校验可选 checksum，并下载 source script。
  3. 脚本会缓存到本机。builtin-js 用内置 QuickJS 执行，不需要 Node.js；其他 runtime 可为 node、python、pwsh、bash 或绝对路径。
  4. 每次刷新时，QuotaBarWin 运行缓存脚本，并归一化为标准额度窗口。

同一个 manifest 可以安装多次，用于查询同一 Provider 的多个账号。QuotaBarWin 会生成 kimi-coding、kimi-coding-2 这类稳定的本地 Provider id。

Manifest 格式

将 manifest 保存为 provider.json，并放在 source script 旁。

{
  "schemaVersion": 2,
  "id": "kimi-coding",
  "displayName": "Kimi Coding Usage",
  "version": "1.1.0",
  "minAppVersion": "1.1.0",
  "description": "Kimi coding quota usage via remote provider script.",
  "runtime": "builtin-js",
  "entry": "provider.js",
  "requiredEnvVars": ["KIMI_API_KEY"],
  "output": "provider-snapshot-v1",
  "permissions": ["env:KIMI_API_KEY", "net:https://api.kimi.com"],
  "defaultConfig": {
    "name": "Kimi",
    "visibleWindowIds": ["300-minute", "usage"],
    "windowLabelOverrides": {
      "300-minute": "5小时限",
      "usage": "周限"
    },
    "envVars": {
      "KIMI_API_KEY": "${secret:KIMI_API_KEY}"
    }
  },
  "parameters": [
    {
      "name": "KIMI_API_KEY",
      "label": "Kimi API Key",
      "kind": "secret",
      "required": true,
      "defaultValue": "${secret:KIMI_API_KEY}"
    }
  ],
  "checksums": {
    "source": "sha256:<hex>"
  }
}
字段必填说明
schemaVersion是1 是旧格式；当前版本仍可加载已缓存的 schema 1 builtin-js 脚本完成升级，但远程安装或更新必须使用 2，让旧本体在下载脚本前安全拒绝更新。
id是稳定 manifest id。重复安装同一 manifest 时，QuotaBarWin 会生成不冲突的本地 Provider id。
displayName是UI 中显示的人类可读名称。
version否设置页显示的人类可读版本号；缺省时显示短 checksum。
minAppVersionschema 2 是最低 QuotaBarWin SemVer 版本，不带 v 前缀，例如 1.1.0。
runtime是builtin-js 使用内置 QuickJS；也可为外部命令名或绝对路径。
entry是Source 文件。相对路径按 manifest 所在位置解析。
requiredEnvVars否脚本需要的环境变量。
output是当前使用 provider-snapshot-v1。
defaultConfig否首次安装时写入本地 provider 配置的默认值。后续更新不会覆盖用户修改。
parameters否设置页显示的参数提示；不要包含真实凭据。
checksums.source否Source SHA-256。启用安全 auto-update 时需要；version 只用于展示，不替代 checksum。

Registry 格式

Registry 可以用一个 URL 安装多个 Provider。

{
  "schemaVersion": 2,
  "providers": [
    {
      "id": "kimi-coding",
      "providerUrl": "kimi-coding/provider.json",
      "checksum": "sha256:<manifest-sha256>"
    }
  ]
}

providerUrl 可以是 HTTPS URL、file:// URL 或本地路径；相对路径会按 registry 所在位置解析。

内置 JavaScript runtime（builtin-js）

builtin-js 不需要安装 Node.js。新发布或远程更新的 manifest 必须使用 schemaVersion: 2 并声明 minAppVersion；入口是 .js，必须定义同步的 main(qb) 并直接返回 provider-snapshot-v1 对象；不要使用 console.log、stdout 或 process.exit。

function main(qb) {
  const token = qb.env.get("EXAMPLE_API_TOKEN");
  const response = qb.http.request("https://api.example.com/usage", {
    headers: { Authorization: `Bearer ${token}` }
  });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  qb.log({ level: "info", stage: "snapshot.ready", message: "Usage loaded" });
  return { status: "ok", updatedAt: qb.now(), windows: [] };
}
API需要的 permission边界
qb.env.get / getOptionalenv:NAME 或 env-prefix:PREFIX_读取已配置变量；getOptional 未配置时返回 null。
qb.fs.readTextfs:路径 或 fs:env:NAME只读 UTF-8，规范化实际路径后拒绝未授权访问。
qb.http.requestnet:http、net:https 或精确 origin同步请求，返回 {status, ok, body}；代理与超时由宿主处理。
qb.now、qb.timezone、qb.log、qb.meta无通用时间、结构化日志和只读 Provider 元信息。

可用同步 JavaScript、Date、JSON、RegExp、Map 和 Set。没有 Promise、import、require、Node/Bun/Deno API、process、console、子进程、任意 socket、任意文件访问或动态加载；内存 16 MiB、JS 栈 512 KiB，并受 Provider timeoutSeconds 限制。QBWIN_ 是保留前缀，不能授予 env/file 访问；元信息用 qb.meta，代理由 qb.http 自动使用。URL、鉴权格式和响应解析仍属于 Provider 脚本，不属于平台。

更新前会校验 schema 与最低版本。本体版本不足时不会改写缓存、配置或旧脚本；只支持 schema 1 的旧版应用也会在下载新 source 前拒绝 schema 2 manifest，避免自动更新造成 Provider 不可运行。当前版本仍可运行已缓存的 schema 1 builtin-js Provider，但不会远程安装或更新这类旧 manifest。

Source Script 输出协议

外部 runtime 脚本必须向 stdout 输出一个 JSON 对象，诊断写 stderr。builtin-js 从 main(qb) 直接返回同形状对象，并通过 qb.log() 写日志。

id、name 和 source 可以省略；即使脚本提供，QuotaBarWin 也会优先使用本地安装配置中的 Provider id 和名称，以支持多账号实例。

{
  "status": "ok",
  "updatedAt": "2026-06-12T10:00:00.000Z",
  "windows": [
    {
      "id": "weekly",
      "label": "Weekly limit",
      "remaining": 88,
      "used": 12,
      "limit": 100,
      "unit": "requests",
      "usedPercent": 12,
      "remainingPercent": 88,
      "warningRemaining": 20,
      "resetAt": "2026-06-19T10:00:00.000Z",
      "resetText": null,
      "confidence": "exact"
    }
  ],
  "metadata": {}
}
请保持 windows[].id 稳定。用户会用它配置窗口顺序、可见性和自定义名称。

本地配置与 Secret

远程脚本不应该包含凭据。外部 runtime 读取 process.env.NAME；builtin-js 使用受 permission 约束的 qb.env.get("NAME")。

单账号可直接使用 <config-dir>/secrets/KIMI_API_KEY.txt 这类同名 secret。多账号时，在每个账号实例的“环境变量”里显式映射：等号左侧保持脚本需要的变量名，右侧换成该账号的 secret 名。 

{
  "kind": "remote",
  "id": "kimi-coding",
  "name": "Kimi Personal",
  "envVars": {
    "KIMI_API_KEY": "${secret:KIMI_API_KEY_PERSONAL}"
  }
}
{
  "kind": "remote",
  "id": "kimi-coding-2",
  "name": "Kimi Work",
  "envVars": {
    "KIMI_API_KEY": "${secret:KIMI_API_KEY_WORK}"
  }
}

上面会分别读取 <config-dir>/secrets/KIMI_API_KEY_PERSONAL.txt 和 <config-dir>/secrets/KIMI_API_KEY_WORK.txt；配置中只保存占位符，不保存明文 token。

实现示例：Zhipu / BigModel

以下示例调用 Zhipu / BigModel quota endpoint，并输出 provider-snapshot-v1。 它们都从 BIGMODEL_API_KEY 读取 API key。

Node.js

const token = process.env.BIGMODEL_API_KEY;
if (!token) {
  console.error("BIGMODEL_API_KEY is required");
  process.exit(1);
}

fetch("https://open.bigmodel.cn/api/monitor/usage/quota/limit", {
  headers: { Authorization: `Bearer ${token}` }
})
  .then((res) => {
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  })
  .then((body) => {
    const limits = body.data?.limits ?? [];
    const windows = limits.map((l) => ({
      id: `${l.type}-${l.unit}-${l.number}`.toLowerCase(),
      label: `${l.type} / ${l.unit}`,
      used: l.currentValue ?? null,
      limit: l.usage ?? null,
      unit: l.type === "TOKENS_LIMIT" ? "tokens" : null,
      usedPercent: l.percentage ?? null,
      remainingPercent: l.percentage == null ? null : Math.max(0, 100 - l.percentage),
      resetAt: l.nextResetTime ? new Date(l.nextResetTime).toISOString() : null,
      resetText: null,
      confidence: "exact"
    }));
    console.log(JSON.stringify({
      status: "ok",
      updatedAt: new Date().toISOString(),
      windows,
      metadata: {}
    }));
  })
  .catch((err) => {
    console.error(err.message);
    process.exit(1);
  });

Python

import json, os, sys, urllib.request, datetime

token = os.environ.get("BIGMODEL_API_KEY")
if not token:
    sys.exit("BIGMODEL_API_KEY is required")

req = urllib.request.Request(
    "https://open.bigmodel.cn/api/monitor/usage/quota/limit",
    headers={"Authorization": f"Bearer {token}"}
)

with urllib.request.urlopen(req) as res:
    body = json.load(res)

limits = body.get("data", {}).get("limits", [])
windows = []
for l in limits:
    pct = l.get("percentage")
    windows.append({
        "id": f"{l['type']}-{l['unit']}-{l['number']}".lower(),
        "label": f"{l['type']} / {l['unit']}",
        "used": l.get("currentValue"),
        "limit": l.get("usage"),
        "unit": "tokens" if l.get("type") == "TOKENS_LIMIT" else None,
        "usedPercent": pct,
        "remainingPercent": None if pct is None else max(0, 100 - pct),
        "resetAt": datetime.datetime.fromtimestamp(
            l["nextResetTime"] / 1000, tz=datetime.timezone.utc
        ).isoformat() if l.get("nextResetTime") else None,
        "resetText": None,
        "confidence": "exact"
    })

print(json.dumps({
    "status": "ok",
    "updatedAt": datetime.datetime.now(datetime.timezone.utc).isoformat(),
    "windows": windows,
    "metadata": {}
}, ensure_ascii=False))

PowerShell

$token = $env:BIGMODEL_API_KEY
if (-not $token) { throw "BIGMODEL_API_KEY is required" }

$res = Invoke-RestMethod -Uri "https://open.bigmodel.cn/api/monitor/usage/quota/limit" -Headers @{
  Authorization = "Bearer $token"
}

$windows = @()
foreach ($l in $res.data.limits) {
  $pct = $l.percentage
  $windows += @{
    id = "$($l.type)-$($l.unit)-$($l.number)".ToLower()
    label = "$($l.type) / $($l.unit)"
    used = $l.currentValue
    limit = $l.usage
    unit = if ($l.type -eq "TOKENS_LIMIT") { "tokens" } else { $null }
    usedPercent = $pct
    remainingPercent = if ($null -eq $pct) { $null } else { [math]::Max(0, 100 - $pct) }
    resetAt = if ($l.nextResetTime) {
      ([DateTimeOffset]::FromUnixTimeMilliseconds($l.nextResetTime).UtcDateTime).ToString("o")
    } else { $null }
    resetText = $null
    confidence = "exact"
  }
}

@{
  status = "ok"
  updatedAt = (Get-Date).ToString("o")
  windows = $windows
  metadata = @{}
} | ConvertTo-Json -Depth 10

Bash（Git Bash）

#!/usr/bin/env bash
set -euo pipefail

TOKEN="${BIGMODEL_API_KEY:-}"
[ -z "$TOKEN" ] && { echo "BIGMODEL_API_KEY is required" >&2; exit 1; }

RESPONSE=$(curl -fsS -H "Authorization: Bearer $TOKEN" \
  "https://open.bigmodel.cn/api/monitor/usage/quota/limit")

UPDATED_AT=$(date -u +"%Y-%m-%dT%H:%M:%SZ")

WINDOWS=$(echo "$RESPONSE" | jq '[.data.limits[] | {
  id: "\(.type)-\(.unit)-\(.number)" | ascii_downcase,
  label: "\(.type) / \(.unit)",
  used: .currentValue,
  limit: .usage,
  unit: (if .type == "TOKENS_LIMIT" then "tokens" else null end),
  usedPercent: .percentage,
  remainingPercent: (if .percentage == null then null else [0, 100 - .percentage] | max end),
  resetAt: (if .nextResetTime == null then null else (.nextResetTime / 1000 | strflocaltime("%Y-%m-%dT%H:%M:%SZ")) end),
  resetText: null,
  confidence: "exact"
}]')

jq -n --arg updatedAt "$UPDATED_AT" --argjson windows "$WINDOWS" \
  '{status: "ok", updatedAt: $updatedAt, windows: $windows, metadata: {}}'
Bash 示例需要 jq。Windows 上 Git Bash 通常会随附它。

安全检查清单

  • 只安装使用可信任的远程 Provider。Provider 脚本可以直接读取你配置给它的各类 AI 鉴权信息，并发起网络通讯。
  • 安装前检查 source URL、runtime 和 required env vars。
  • 优先使用带 providers[].checksum 的 registry。
  • 优先使用带 checksums.source 的 manifest；否则无法安全自动更新。
  • 缓存 source 位于 app data 目录下的 providers/remote/<id>/，这里的 <id> 是本地安装实例 id。

示例与更新

仓库中的 examples/remote-providers/ 包含 Kimi、BigModel、Codex usage 和 DeepSeek balance 示例。

如果 manifest 包含 checksums.source，可在设置页使用自动更新或手动 “检查更新 / 应用更新”。设置页会显示版本、安装时间、更新时间和上次检查时间。缺少 checksum 时，需要移除后重新添加 Provider。

Remote Provider Guide

Install quota providers from a hosted manifest and script, without bundling them into the app.

中文 English

How it works

  1. You provide a registry URL or local file path such as registry.json.
  2. QuotaBarWin reads the registry, fetches each provider manifest, verifies optional checksums, and downloads source scripts.
  3. Each script is cached locally. builtin-js uses embedded QuickJS and needs no Node.js; other runtimes can be node, python, pwsh, bash, or an absolute path.
  4. On every refresh, QuotaBarWin runs the cached scripts and normalizes their results into quota windows.

The same manifest can be installed more than once for multiple accounts. QuotaBarWin generates stable local provider ids such as kimi-coding and kimi-coding-2.

Manifest format

Save the manifest as provider.json next to your source script.

{
  "schemaVersion": 2,
  "id": "kimi-coding",
  "displayName": "Kimi Coding Usage",
  "version": "1.1.0",
  "minAppVersion": "1.1.0",
  "description": "Kimi coding quota usage via remote provider script.",
  "runtime": "builtin-js",
  "entry": "provider.js",
  "requiredEnvVars": ["KIMI_API_KEY"],
  "output": "provider-snapshot-v1",
  "permissions": ["env:KIMI_API_KEY", "net:https://api.kimi.com"],
  "defaultConfig": {
    "name": "Kimi",
    "visibleWindowIds": ["300-minute", "usage"],
    "windowLabelOverrides": {
      "300-minute": "5h",
      "usage": "Weekly"
    },
    "envVars": {
      "KIMI_API_KEY": "${secret:KIMI_API_KEY}"
    }
  },
  "parameters": [
    {
      "name": "KIMI_API_KEY",
      "label": "Kimi API Key",
      "kind": "secret",
      "required": true,
      "defaultValue": "${secret:KIMI_API_KEY}"
    }
  ],
  "checksums": {
    "source": "sha256:<hex>"
  }
}

Provider registry format

A registry installs multiple providers from one URL.

{
  "schemaVersion": 1,
  "providers": [
    {
      "id": "kimi-coding",
      "providerUrl": "kimi-coding/provider.json",
      "checksum": "sha256:<manifest-sha256>"
    }
  ]
}

providerUrl may be an HTTPS URL, file:// URL, or local path. Relative paths are resolved against the registry URL/path.

Embedded JavaScript runtime (builtin-js)

builtin-js needs no installed Node.js. A newly published or remotely updated manifest must use schemaVersion: 2 and declare minAppVersion; its .js entry defines synchronous main(qb) and returns a provider-snapshot-v1 object directly; do not use console.log, stdout, or process.exit.

function main(qb) {
  const token = qb.env.get("EXAMPLE_API_TOKEN");
  const response = qb.http.request("https://api.example.com/usage", {
    headers: { Authorization: `Bearer ${token}` }
  });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  qb.log({ level: "info", stage: "snapshot.ready", message: "Usage loaded" });
  return { status: "ok", updatedAt: qb.now(), windows: [] };
}
APIRequired permissionBoundary
qb.env.get / getOptionalenv:NAME or env-prefix:PREFIX_Reads configured values; getOptional returns null when absent.
qb.fs.readTextfs:path or fs:env:NAMEUTF-8 read only; canonical real paths outside the grant are rejected.
qb.http.requestnet:http, net:https, or an exact originSynchronous request returning {status, ok, body}; the host handles proxy and timeout.
qb.now, qb.timezone, qb.log, qb.metanoneGeneric time, structured log, and read-only Provider metadata.

Use synchronous JavaScript, Date, JSON, RegExp, Map, and Set. Promises, import, require, Node/Bun/Deno APIs, process, console, subprocesses, arbitrary sockets, arbitrary files, and dynamic loading are unavailable. Limits are 16 MiB memory, a 512 KiB JS stack, and Provider timeoutSeconds. QBWIN_ is reserved and cannot be granted env/file access; use qb.meta for metadata and let qb.http use the proxy. URLs, auth formats, and response parsing remain Provider-owned.

The host validates the schema and minimum app version before an update. A host that is too old leaves its cached source and configuration untouched; apps that support only schema 1 reject schema 2 before downloading the new source, preventing an automatic update from making a Provider unrunnable. The current app still runs an already cached schema 1 builtin-js Provider, but will not install or update one remotely.

Source script output contract

External-runtime scripts print one JSON object to stdout and write diagnostics to stderr. builtin-js returns the same-shaped object from main(qb) and logs through qb.log().

id, name, and source are optional; even when provided, QuotaBarWin prefers the local installed provider id and name so one manifest can back multiple accounts.

{
  "status": "ok",
  "updatedAt": "2026-06-12T10:00:00.000Z",
  "windows": [
    {
      "id": "weekly",
      "label": "Weekly limit",
      "remaining": 88,
      "used": 12,
      "limit": 100,
      "unit": "requests",
      "usedPercent": 12,
      "remainingPercent": 88,
      "warningRemaining": 20,
      "resetAt": "2026-06-19T10:00:00.000Z",
      "resetText": null,
      "confidence": "exact"
    }
  ],
  "metadata": {}
}
Keep windows[].id stable. User customization depends on it for display order, visibility, and labels.

Local config and secrets

Remote provider source should not contain credentials. External runtimes read process.env.NAME; builtin-js uses permission-gated qb.env.get("NAME").

A single account can use a same-name secret such as <config-dir>/secrets/KIMI_API_KEY.txt. For multiple accounts, set each account instance's Environment variables explicitly: keep the left side as the script env var and change the secret name on the right. 

{
  "kind": "remote",
  "id": "kimi-coding",
  "name": "Kimi Personal",
  "envVars": {
    "KIMI_API_KEY": "${secret:KIMI_API_KEY_PERSONAL}"
  }
}
{
  "kind": "remote",
  "id": "kimi-coding-2",
  "name": "Kimi Work",
  "envVars": {
    "KIMI_API_KEY": "${secret:KIMI_API_KEY_WORK}"
  }
}

These examples read <config-dir>/secrets/KIMI_API_KEY_PERSONAL.txt and <config-dir>/secrets/KIMI_API_KEY_WORK.txt; the config stores placeholders, not plain tokens.

Bash (Git Bash)

#!/usr/bin/env bash
set -euo pipefail

TOKEN="${BIGMODEL_API_KEY:-}"
[ -z "$TOKEN" ] && { echo "BIGMODEL_API_KEY is required" >&2; exit 1; }

RESPONSE=$(curl -fsS -H "Authorization: Bearer $TOKEN" \
  "https://open.bigmodel.cn/api/monitor/usage/quota/limit")

UPDATED_AT=$(date -u +"%Y-%m-%dT%H:%M:%SZ")

WINDOWS=$(echo "$RESPONSE" | jq '[.data.limits[] | {
  id: "\(.type)-\(.unit)-\(.number)" | ascii_downcase,
  label: "\(.type) / \(.unit)",
  used: .currentValue,
  limit: .usage,
  unit: (if .type == "TOKENS_LIMIT" then "tokens" else null end),
  usedPercent: .percentage,
  remainingPercent: (if .percentage == null then null else [0, 100 - .percentage] | max end),
  resetAt: (if .nextResetTime == null then null else (.nextResetTime / 1000 | strflocaltime("%Y-%m-%dT%H:%M:%SZ")) end),
  resetText: null,
  confidence: "exact"
}]')

jq -n --arg updatedAt "$UPDATED_AT" --argjson windows "$WINDOWS" \
  '{status: "ok", updatedAt: $updatedAt, windows: $windows, metadata: {}}'
For Bash, jq must be available. On Windows, Git Bash usually ships with it.

Security checklist

  • Only install and use remote providers you trust. Provider scripts can directly read the AI credentials configured for them and make network requests.
  • Review source URL, runtime, and required env vars before installing.
  • Prefer registries that include providers[].checksum.
  • Prefer manifests that include checksums.source; without it QuotaBarWin cannot auto-update safely.
  • The cached source lives under providers/remote/<id>/ in the app data directory, where <id> is the local installed instance id.

Examples and updates

The repository's examples/remote-providers/ directory contains Kimi, BigModel, Codex usage, and DeepSeek balance examples.

If the manifest contains checksums.source, use auto-update or the Settings page's Check Updates / Apply Update actions. Settings shows the version, install time, update time, and last check time. Without a checksum, remove and re-add the provider to update it.
