Custom Provider Guide

QuotaBarWin can run a local script and read the JSON it prints. Use this when a quota source is not covered by a built-in provider.

Quick Start

  1. Add Custom Script Provider in Settings.
  2. Set Executable to node, python, powershell, or a full executable path.
  3. Put one command-line argument per line in Args. Usually this is the script path.
  4. Set Output contract to provider-snapshot-v1.
  5. Click Test Provider and check the JSON result.

Minimum Output

Your script should print one JSON object to stdout.

{
  "status": "ok",
  "windows": [
    {
      "id": "weekly",
      "label": "Weekly",
      "used": 12,
      "limit": 100,
      "unit": "requests",
      "confidence": "exact"
    }
  ]
}

Node.js Example

console.log(JSON.stringify({
  status: "ok",
  windows: [
    {
      id: "weekly",
      label: "Weekly",
      used: 12,
      limit: 100,
      unit: "requests",
      confidence: "exact"
    }
  ]
}));

Common Fields

id
A stable window id, such as daily, 5h, or weekly.
label
The text shown in QuotaBarWin.
used
The amount already consumed.
limit
The total amount available in the same unit as used.
unit
Examples: requests, tokens, minutes, or percent.
confidence
Use exact for source-of-truth values or estimated for inferred values.

Secrets

Settings support placeholders, so secrets do not have to be stored directly in the config.

  • ${env:API_KEY} reads an environment variable.
  • ${file:C:\Secrets\api-key.txt} reads a local file.

Output Contracts

provider-snapshot-v1
One provider result. This is the usual choice for a custom script.
app-snapshot-v1
Multiple providers in one app-level JSON object.

What QuotaBarWin Adds

Provider id, provider name, source, diagnostics, and percentages are filled in when possible. Secret values are hidden from diagnostics.
