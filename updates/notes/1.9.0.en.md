## [1.9.0] - 2026-11-10

### Added

- Providers now have a permanent **Configure** entry: ready providers can be opened any time to inspect credential status or replace/clear credentials, instead of the button only appearing for pending/unverified ones.
- Credential rows gained **Copy** and **Reveal**: copies are excluded from Windows clipboard history and cloud clipboard sync; one click reveals the value, which can be hidden manually.
- One-click **Move to app-managed**: migrates a plaintext credential stored in the config file into the app-managed store (encryption follows the secret-security setting). The plaintext disappears from the config file and the provider keeps its state without re-verification.

### Changed

- Saving after changing only the account name no longer marks a provider unverified and disabled; a new test is required only when a credential binding or a runtime parameter actually changes.
- Deleting or editing a credential binding in the advanced env editor now also marks the provider unverified and disabled, matching the Configure page.
- The advanced env editor hides app-managed bindings by default with a new **Show managed bindings** toggle; undeclared variables are listed read-only on the Configure page.

### Fixed

- Fixed config loss in concurrent flows: saving settings while an update check or credential test is running no longer overwrites the other side's changes with a stale snapshot, and plaintext credentials are never written back.
- Fixed clicking a credential field's title or hint text accidentally triggering the **Clear** action; clicking a field title now focuses its input, and screen readers announce the **Clear** button as just "Clear".

### Security

- Config writes are now atomic replace-on-rename, so a failed write can no longer leave a truncated half-written config behind.
- Reveal/copy actions are audited in logs that never contain the secret value.
